# 第十轮 · 连续推流打通与默认配置定案

> 2026-11-22。目标：把"能解出帧"推进到"一直有帧"。结论：**做到了**，`live.bat` 默认配置即可连续推流、无花屏，帧率 13~25fps。

## 1. 一句话结论

把三件事同时改对之后，相机不再在 45~55 秒处关流：

1. **不裁剪磁带**（`CUT=0`）：旧默认 `CUT=7.0` 连带砍掉了冷启动那段"切 app 模式"的顺序，是"十几帧天花板"的一部分原因；
2. **循环段覆盖健康期**（`CYCLE_FROM=6.30`、`CYCLE_TO=54`、`LOOP_TO=54`），一轮 ≈47.7s，一轮接一轮，**含磁带自带的 ack/treq 骨架**（不再剔除）；
3. **时钟再戳 + 正确 ack**（`RESTAMP=1`、`ACK=1 ACK_MODE=clk`）：每轮都用相机刚发的 35B stream-check 重算片上时钟偏移，而不是按轮次累加估计；ack 用虚拟客户端时钟（真机 ack 是同一个 2.34MHz 单调钟的三次采样）。

## 2. 本轮 A/B 实测表（同一台相机、同一份 up9004.bin）

| 配置 | 帧数 | 时长 | 结果 |
|---|---|---|---|
| CUT=0 / LOOP=54 / 无循环 / 无 ack | 735 | ~48s | 磁带结尾即停 |
| CUT=0 / LOOP=45 / 循环 6.3~45 / 无 ack | 783 | ~43s | 停止点跟 LOOP_TO 走 |
| CUT=0 / LOOP=54 / 无循环 / 无 ack | 921 | ~53s | 同上 |
| CUT=0 / LOOP=38 / 循环 6.3~38 / RESTAMP / 无 ack | 668 | ~31s | 更早停，说明"截短"本身有害 |
| **CUT=0 / LOOP=54 / 无循环 / ACK=clk / TREQ=0** | **949** | **>150s** | **没死，但掉到 ~1fps** |
| **CUT=0 / LOOP=54 / 无循环 / ACK=clk / TREQ=10** | **1208** | **>150s** | 同上，前 55s 17fps，之后涓流 |
| **CUT=0 / LOOP=54 / 循环 6.3~54 / RESTAMP / ACK=clk / TREQ=10** | **2720+（持续增长）** | **>150s** | ✅ 打通：后段稳定 25fps |

决定性对比：**ACK=0 时必在磁带结尾附近停流；ACK=clk 后跨过结尾继续收**。所以"16 帧天花板/45 秒掉流"的直接开关是 ack 的正确性，而不是电量、不是丢包、不是拼片。

## 3. 端到端验收（`live.bat --secs 95 --no-window`）

```
[live] 就绪（已抓到 IDR）… idr=1
[live] 第 1 轮收到 1254 帧；frames=1367 incomplete=274 idr=1
[live] 结束，累计 1254 帧 / 95.8s
```

* 相机端组装 1367 帧 / 93s ≈ **14.7 fps**，PC 端取走 1254 帧（队列丢 4 帧）⇒ 全链路无重建、无重启；
* 离线解码 `samples/g74.h264`：**conceal 行 = 0**，318 帧 / 20.2s = 15.7fps；
* 画面指标 `g74_f318.png`：`lap_top=186.9 / lap_bot=218.0`（基准 42~198 / 82~121），**远高于历史上任何一帧**。

## 4. 代码改动

`probe/live_server.py`
1. `session_keeper()` 循环体：`span<=0.02` 时旧代码只把 span 设 1.0 却不 pace，导致"55 条订阅一届循环"被刷了 28880 遍（对相机 UDP 洪水）。改为按 0.1s 一条匀开。
2. 新增 `LIVE_RESTAMP=1`：每轮取 `ACK["last_chk"]` 与 `ACK["tpl"]` 三对字段求差取中位，作为本轮 delta（替代 `k*span*1000` 的死算）。
3. 新增 `LIVE_CYCLE_FROM=full|whole`：整盘循环模式（含开场模式包与收尾），供"周期性重开预览"实验用。
4. `ACK_MODE=clk` 成为实测最佳档（虚拟 2.338e6 单位/秒客户端时钟）。

`osmo360/live.py`
1. `pkill -f 'live_serve[r].py'`（原写法会匹配到执行命令的 adb shell 自身，exit 143）。
2. 默认远端环境整体换成第十轮胜出组合（见 §1），并逐条写清原因。

## 5. 仍未解决

* **帧率不是恒定 25fps**：设备端 25fps 的时段与 ~10~15fps 的时段交替，`incomplete` 稳定 3/s（每 8 帧丢 1 帧）。下一步要抓"丢片现场"（`LIVE_DUMP_SEC` 取证开关已修好可用）。
* 相机 `stream_source_num 0`、8324 条 `wait async ack timeout host 0x0200 msg_id 0x99` 仍未定案。
* `ensure.py/ensure.bat`、`README.md`、`HANDOFF.md` 未同步到本轮配置。
