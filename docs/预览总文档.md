## 1. 目标与验收

在 PC 上直接取得 Osmo 360 的实时预览流，不依赖手机 App、不截屏、不拍屏。验收：流畅、不丢包、不花屏、无空档。

## 3. 协议

下行大包 1472 字节：

```
[16] 类型   [17] 通道号   [18] 通道内序号   [19:23] == 00 00 00 01   [23:] 载荷
```

剥壳：`p[19:]`（当 `p[19:23] == 00000001`），否则 `p[20:]`。

内层 DUML：

```
55 <len> <crc8> <发送方> <接收方> <seq 2B> <flags> <cmd_set> <cmd_id> <payload> <crc16>
```

上行 magic `80 40 34`，下行 magic `80 0e 8a`；`[6]`：`0x05` 请求 / `0x04` ACK / `0x00` 保活。

## 4. 突破一：会话不再被 12 秒踢掉

相机侧 `sys_host_check_status_ti` 在重试耗尽后调用 `sys_host_task_sm_down`，正好 12 秒判死。
打补丁：文件偏移 `0x5d2f8`，`b.ne`（`54 00 02 c1`）→ 无条件 `b`（`14 00 00 16`），只改进程内存。

```bash
python3 /data/local/tmp/gate_off.py     # 输出 after write=14000016 OK
```

实测：600–666 大包/秒（≈26 fps），连续 78 秒零断流、重复包 0、缺口 0。回滚 = `systemctl restart dji_system`。

## 5. 突破二：拿到 SPS/PPS/IDR

日志证据：

```
[ djiwlc2venc ] print_c2_venc_property: [liveview] wl_plugin config idr_interval : 1000000.
```

`idr_interval = 1000000` ⇒ 编码器**只在实例创建时吐一个 IDR**，此后只有 P 帧。因此必须让“实例创建”发生在我们已连着的时候：

> **先连客户端 → 再中途重启编码器进程。**

```bash
systemctl restart dji_sw_uav; sleep 3
tcpdump -i lo -n -s 0 -w /dev/shm/sX.pcap udp &
python3 /data/local/tmp/lv_fix.py /dev/shm/mimo.pcap 32 20 &
sleep 6
systemctl restart dji_camera3
```

实测命中（21.4 MB / 22 秒抓包）：

```
SPS @ 6,210,886   00000001 67 64 00 28 ac b4 01 00 04 0d 35 …
PPS @ 6,210,908   00000001 68 ee 06 f2 c0
IDR @ 6,210,917   00000001 65 …
```

## 6. 解码

```bash
python probe/ch_sum.py samples/sX.pcap                  # 逐通道：字节数 / SPS / IDR
python probe/cut_from.py samples/sX.pcap <SPS偏移>       # samples/_dec.h264
ffmpeg -y -f h264 -i samples/_dec.h264 -fps_mode passthrough out_%03d.png
```

结果：`Stream #0:0: Video: h264 … 2048x1024, 25 fps`，零报错。
该档参数集（31 字节）恒定可复用：

```
00000001 67640028 acb40100 040d3501 010106d0 a135
00000001 68 ee06f2c0
```

## 7. 通道分布

| 通道 | 字节 | SPS | IDR | 含义 |
|---|---|---|---|---|
| 0x20 / 0xa0 / 0x22 / 0xa2 / 0x21 / 0xa1 | 各 1.8–1.97 MB | 无 | 无 | 全景 6000×3000 六分片 |
| 0x92 | 1.30 MB | 无 | 有 | 带 I 帧的通道 |
| 0x0d | 9,130 B | 有 | 有 | 2048×1024 预览小流 |

## 8. 实时观看

拿到一次 IDR 后，靠零丢包一直解 P 帧即可，不需要周期性关键帧：

```bash
ffmpeg -f h264 -i - -fps_mode passthrough -f sdl "Osmo Preview" < stream.h264
```

## 9. 控制面

```bash
cd /usr/lib
LD_PRELOAD=/data/local/tmp/hk/libdcam_hook.so:libqcom_adapter.so \
  dji_cst -d cst -u -f -m <序列名> -l /tmp/x.log
grep -a -E "CST_RLT|CST_Summary" /tmp/x.log
```

| 类别 | 序列 |
|---|---|
| 预览 | `duss_liveview_6000x3000_pano_video_p25` |
| 模式 | `duss_mode_profile_switch`、`duss_cap_mode_switch`、`duss_rec_mode_switch`、`duss_pano_rec_mode_switch` |
| 参数 | `Binder_SetISO`、`SetShutterSpeed`、`SetExpoMode`、`test_3a_ev_setting`、`test_dzoom_*` |
| 录像 | `duss_record_*`（2688×1512 ~ 7680×3840 全景 p60） |
| 拍照 | `osmo_shot`、`duss_single_capture_*`（含 4s / 8s 长曝光） |

录像前挂好卡：`mkdir -p /mnt/media_rw/sd && mount -t exfat /dev/mmcblk1p1 /mnt/media_rw/sd`
