# Rammer —— 传感器画质上限专题

## 这个分区是干什么的

`Rammer`（夯锤）只做一件事：**把这台相机的画质/采集上限往上顶**。
它不负责"能实时看到画面"（那是主线的 `docs/04` 与 `tools/pc/r147/r148`），
两者互不干扰：主线要的是"低延迟能看"，这里要的是"每帧有多少信息量"。

## 边界（先说清楚不做什么）

- 不改机身屏、不动 GUI、不破坏 adb —— 与主线同一套红线。
- 不以"好看"为标准，以**可量化指标**为标准：分辨率、位深、帧率真伪、码率、动态范围、可用视角、暗光信噪比。
- 所有结论必须能被脚本复现（脚本放 `rammer/tools/`，样本放 `rammer/data/`）。

## 三条当前已知的"上限线索"

1. **采集档不止一档**：`/system/etc/cst_cases.json` 里有 `1X1_1920P`（已实测 119.88fps）、
   `3840x1920`、`5120x3840`、`7680x3840` 等 case —— 高分辨率档还没逐个验证。
2. **位深是 10bit**：`.OSV` 实测 `hevc Main 10 / yuv420p10le`，说明 ISP→编码链路本来就是 10bit，
   那么"能不能拿到 10bit 的未压缩/浅压缩源"是关键问题。
3. **单镜 1920×1920 圆形鱼眼是原始视角**（不是拼好的等距柱状），
   对训练类用途来说这比 2:1 拼接图更"生"，也更少插值损失。

## 怎么加一条实验

1. 在 `R0N_主题.md` 里写清：假设、方法、判据（数值）、结论、回滚方式。
2. 脚本放 `rammer/tools/r2NN_*.py`（与主线 `tools/pc/r1xx` 号段分开，避免混号）。
3. 样本只放"能复现判据的最小集"，原始大文件留在 `samples/rec/` 并在文档里写清路径与校验值。
