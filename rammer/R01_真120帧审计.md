# R01 真 120 帧审计 —— 用户那段 4K 120fps 到底是不是真 120

日期：2026-11-26
样本：`CAM_20261126212523_0068`（用户用机身录的一段）

## 一、规格（ffmpeg 读出）

```
c68.OSV (269,519,371 B)
  hevc (Main 10) hvc1, yuv420p10le(tv, bt709), 1920x1920, 119.88 fps, 69612 kb/s
  duration 15.30 s, 总码率 140962 kb/s
c68.LRF (16,260,183 B)
  h264 (High) avc1, yuv420p(tv, bt709), 2048x1024, 29.97 fps
  duration 15.32 s, 8493 kb/s
```

注意：这次是 `RESOLUTION_1X1_1920P` —— **1:1 单镜圆形鱼眼**，不是拼好的 2:1 等距柱状。
画面见 `data/c68_firstframe_960.jpg`。

## 二、判据一：帧数

```
解出 1833 帧 / 15.30 s = 119.80 fps
```

与容器标注 119.88 一致（差 0.07%，属首尾采样误差，可忽略）。

## 三、判据二：有没有"重复帧凑数"

把全片降到 192×192 灰度，逐帧求平均绝对差：

```
相邻帧差：min 0.59   p10 0.77   中位 0.90   max 6.26
阈值 0.30 → 1833/1833 帧有新内容（100%），最长连续重复段 = 0 帧
```

**没有任何一对相邻帧是相同的**。若编码器是把 30fps 复制 4 份，会成片出现 `diff≈0`，
这里一次都没有。

## 四、判据三：帧差是否随时间间隔线性增长（区分"真采样 vs 噪声")

如果 120 帧其实是同一个 30fps 采样点的重复，那么 lag=4 时会回到 0 差异；
如果是真 120fps 采样，间隔越大画面变化越大，并叠加噪声地板：

| lag(帧) | 间隔(ms) | 帧差中位 | p90 | 零差异占比 |
|---|---|---|---|---|
| 1 | 8.3 | 0.90 | 1.79 | 0.0% |
| 2 | 16.7 | 1.16 | 2.91 | 0.0% |
| 4 | 33.4 | 1.68 | 4.80 | 0.0% |
| 8 | 66.7 | 2.64 | 7.89 | 0.0% |
| 12 | 100.1 | 3.48 | 10.30 | 0.0% |
| 30 | 250.3 | 6.43 | 17.33 | 0.0% |
| 60 | 500.5 | 10.11 | 27.73 | 0.0% |
| 120 | 1001.0 | 15.26 | 31.11 | 0.0% |

单调递增、无平台、无零差异 —— 典型的真实时间采样曲线。

## 五、结论

> **这段 1920×1920 是真正的 119.88fps，1833 帧全部为独立时间采样。**

同时确认三件附带事实：
1. 相机在 pano 模式下确实能跑 **hevc Main10 10bit / ~70Mbps 视频轨**，ISP→编码链路本来就是 10bit。
2. `.LRF` 代理固定 2048×1024@29.97，**不随主轨帧率变化** —— 想验证高帧率只能看 `.OSV`。
3. 单镜 1920×1920 是**圆形鱼眼原视角**，没有做等距柱状投影，属于"最生"的采集形态。

## 六、复现

```powershell
# 导出低分辨率灰度序列（192×192 → 约 67MB）
ffmpeg -i c68.OSV -vf "scale=192:192,format=gray" -fps_mode passthrough -f rawvideo c68_192.raw

python tools\pc\r149_fps_audit.py c68_192.raw 192 15.30     # 帧数/重复帧
python tools\pc\r150_fps_lag.py   c68_192.raw               # 帧差-间隔曲线
```

本目录 `data/c68_96x96_first200.raw` 是前 200 帧的 96×96 灰度（1.76MB），
用 `r150` 把 `W` 改成 96、把 `n` 截到 200 即可复现上表前三行。
